# Objectives for Module 16 - Secure Developer Environment and Security Awareness

This module covers the security of the tools, accounts, and practices developers use to build software, and the security awareness expected of a developer.

A successful candidate can:

- Recognize why developer workstations are high-value targets
- Identify the assets and common threats of a development environment
- Identify workstation-hardening controls, including least privilege, separation of development and production access, disk encryption, screen locking, endpoint protection, host firewalls, patching, and removal of unnecessary software
- Recognize developer responsibilities under organizational security policies, including acceptable use, software installation, data handling, production access, and incident reporting
- Identify security risks of IDEs, editors, extensions, language servers, build tools, command-line utilities, package managers, and Git hooks
- Identify controls for local tools, including trusted sources, restricted permissions, workspace trust, updates, version pinning, and removal of unnecessary tools
- Identify security and data-handling risks of online developer services, code assistants, and other third-party tools
- Recognize information that must not be submitted to online services
- Recognize inappropriate storage, transmission, logging, committing, or sharing of secrets and sensitive data
- Distinguish secrets-management, secret-detection, data-minimization, sanitization, and credential-rotation practices
- Distinguish secure from insecure practices for corporate, home, and public networks, including remote access, Wi-Fi, VPNs, and SSH keys
- Recognize the risks of locally running development servers, databases, administrative interfaces, and debugging services
- Distinguish the security benefits and limitations of containers, virtual machines, development containers, and cloud workspaces
- Recognize unsafe container settings, including privileged execution, unnecessary host mounts, exposed runtime sockets, untrusted images, and exposed host credentials
- Recognize developer-targeted social engineering and supply chain attacks that use phishing, malicious repositories, pull requests, packages, scripts, extensions, or credential requests
- Identify secure everyday practices, including locking unattended devices, using multi-factor authentication (MFA), reviewing commands and Git diffs, and sanitizing logs and screenshots before sharing
- Recognize indicators of a possible workstation, credential, repository, or account compromise
- Identify immediate responses to a suspected compromise, including stopping unsafe activity, revoking or rotating exposed credentials, and reporting through the incident-response process
- Identify sources of security information, including vulnerability advisories, vendor bulletins, organizational guidance, and OWASP resources
- Recognize insecure practices and missing controls in a described developer-environment scenario

## Expected competency

Candidates can distinguish secure from insecure developer-environment practices in ordinary software-development scenarios.
They can select an appropriate control, response, or safer alternative.
