# Objectives for Module 4 - Input Validation and Output Encoding

This module tests the developer for the safe handling of untrusted data in web applications: validating input on the server, preventing injection with safe APIs, and encoding output for the context in which it is used.

A successful candidate can:

- Identify the sources of untrusted data that reach a web application
- Distinguish validation, sanitization, normalization, and output encoding, and recognize the appropriate technique for a given situation
- Recognize allowlist-based, server-side validation of type, length, range, format, and allowed values
- Distinguish client-side validation as a usability aid from server-side validation as a security control
- Recognize how injection vulnerabilities occur when untrusted data changes the meaning of a query, command, or document
- Identify parameterized APIs and secure parser configuration as defenses against SQL, NoSQL, OS command, LDAP, XPath, XML external entity, template, and header injection
- Recognize context-specific output encoding as the defense against cross-site scripting in HTML, attribute, JavaScript, URL, and CSS contexts
- Recognize the use of a maintained HTML sanitizer when an application must accept rich content
- Identify positive and negative test cases for validation rules, injection defenses, and output encoding

## Expected competency

Candidates can recognize whether a web application feature handles untrusted data safely with server-side validation, parameterized APIs, and context-appropriate output encoding.
They can identify injection and cross-site scripting weaknesses caused by missing or incorrect input and output handling.
They can identify the tests that verify these defenses.
