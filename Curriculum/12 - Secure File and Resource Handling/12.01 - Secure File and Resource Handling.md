# Module 12 – Secure File and Resource Handling

This outline defines the file and resource handling knowledge assessed in Module 12.

## 12.1 File upload risks and validation

- Risks of uploaded files: stored malicious content, code execution, denial of service, and exposure to other users
- Validation of the file extension against an allowlist of permitted types
- Why the client-declared Content-Type header and the original file name cannot be trusted
- Content checks, such as file signatures (magic bytes), as a stronger signal than the extension
- Consistency checks between extension, declared type, and detected content
- Limits on file size, request size, and storage per user
- Generating a new file name on the server instead of using the supplied name
- Validation as one layer, combined with safe storage and safe serving

## 12.2 Content type handling and sniffing

- Content-Type response headers that match the actual file content
- Content sniffing, in which a browser guesses a type and may run a file as a script
- The `X-Content-Type-Options: nosniff` header
- Risks of serving user-supplied HTML, SVG, or script files from the application's origin
- Serving untrusted files from a separate domain

## 12.3 Path traversal and file inclusion

- Path traversal as access to files outside an intended directory through sequences such as `../`, absolute paths, and encoded forms
- Avoiding user-controlled values in file paths and using indirect references, such as identifiers, instead
- Canonicalization of a path and the check that the result stays inside an allowed base directory
- Filename sanitization as a weaker control than avoiding user input in paths
- File inclusion: loading or running a file chosen by user input
- Local file inclusion and remote file inclusion as consequences of user-controlled include paths and remote includes
- Allowlisting the files that may be included

## 12.4 Archive extraction

- Zip Slip: archive entries with path traversal sequences that write outside the extraction directory
- Symbolic links inside archives
- Validation of each extracted path against the target directory
- Limits on the number and total size of extracted files to prevent decompression bombs
- Extraction into an isolated directory

## 12.5 File storage

- Storing uploaded files outside the web root or in dedicated storage
- Disabling script execution and directory listing in upload directories
- Non-guessable file names and access control on each file
- Separation of files by sensitivity and least-privilege access for the application account
- Cloud object storage: private buckets by default, pre-signed download URLs, and pre-signed upload URLs or forms
- Expiry and restricted scope of pre-signed URLs, including size and content-type conditions on uploads
- Encryption at rest and access logging for stored files (see Module 8)

## 12.6 File download

- Authorization check before a file is served (see Module 3)
- The `Content-Disposition: attachment` header for files that should be downloaded, not displayed
- The `X-Content-Type-Options: nosniff` header on downloads
- Cache control for sensitive files
- Expiry of download links
- Safe handling of file names in response headers

## 12.7 Temporary files

- Risks of predictable names, shared temporary directories, and weak permissions
- Creating temporary files with unpredictable names and exclusive creation
- Restrictive permissions on temporary files
- Deleting temporary files after use, including after errors
- Race conditions between checking and creating a file (see Module 11)

## 12.8 Server-side request forgery (SSRF)

- SSRF as a server fetching a URL controlled by an attacker, with the server's network position and privileges
- Features that fetch user-supplied URLs: import from URL, image or document retrieval, link previews, and webhooks
- Targets of SSRF: internal services, loopback addresses, and cloud metadata endpoints
- Allowlists of permitted hosts, protocols, and ports as the primary control
- Why denylists of addresses are incomplete, including alternate address encodings
- Resolving the host name and validating the resulting address, and the risk of DNS rebinding
- Redirects as a way to bypass URL checks
- Network-level controls such as egress filtering and restricted access to metadata endpoints
- Limits on response size and time, and not returning raw responses to the user
- The relationship to API security (see Module 13)
