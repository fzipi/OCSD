# Objectives for Module 1 - Secure Design, Architecture and Threat Modeling

This module tests security decisions made by a developer during design and the use of threat modeling to turn risks into development work.

A successful candidate can:

- Recognize how security activities fit into the software development lifecycle
- Identify assets, components, data flows, entry points, trust boundaries (including the web same-origin policy), and security assumptions in a system description
- Recognize the OWASP Top 10 as an overview of common application risks
- Recognize Secure by Design, essential secure design principles, and Zero Trust assumptions in a design
- Identify common design flaws and distinguish them from implementation defects
- Identify the purpose of each question in the Four Question Framework for threat modeling
- Distinguish the STRIDE threat categories and recognize the application context that prioritizes threats
- Recognize usability and human factors as sources of threats
- Recognize agreed mitigations expressed as security requirements, implementation work, and tests
- Identify the assumptions, decisions, and residual risks that a threat model records

## Expected competency

Candidates can review a web application design and contribute to its threat model as part of a team.
They can translate agreed security decisions into development and test work.
