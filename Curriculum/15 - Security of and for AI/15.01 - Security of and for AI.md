# Module 15 – Security of and for AI

This outline defines the AI security knowledge assessed in Module 15.
Part A (15.1 to 15.4) covers the OWASP Top 10 for LLM Applications 2026.
Part B (15.5 to 15.7) covers agentic applications and the Model Context Protocol (MCP).
Candidates are expected to be consumers of models and services, not builders of models.

## Part A – OWASP Top 10 for LLM Applications 2026

## 15.1 The OWASP Top 10 for LLM Applications 2026

- The ten risks by number and name: LLM01 Prompt Injection, LLM02 Sensitive Information Disclosure, LLM03 Excessive Agency, LLM04 Supply Chain, LLM05 Data and Model Poisoning, LLM06 Unbounded Consumption, LLM07 Misinformation, LLM08 Hidden Context Exposure, LLM09 Vector and Embedding Weaknesses, LLM10 Improper Output Handling
- That the 2026 edition changes the numbering of the 2025 edition and renames System Prompt Leakage to Hidden Context Exposure
- The difference between securing an application that uses a model and using AI to help build or secure software
- Why an LLM cannot reliably separate instructions from data, and why this underlies several of the risks
- Why model behavior is not deterministic and why a security control must not depend on the model following instructions

## 15.2 Instructions, hidden context, and model output

- Direct prompt injection through user input and indirect prompt injection through documents, web pages, tool results, and memory (LLM01)
- That input filtering, delimiters, and prompt wording reduce exposure but do not create a trust boundary (LLM01)
- Controls outside the model that limit the impact of injection: least privilege, output validation, and human approval of high-risk actions (LLM01)
- Hidden context as anything in the model's context that the user is not meant to see, such as developer instructions, tool schemas, and policy text (LLM08)
- Why hidden context must be treated as discoverable, and why no secret, credential, or access-control rule may depend on its confidentiality (LLM08)
- Model output as untrusted input to browsers, shells, databases, and other services (LLM10)
- Cross-site scripting, injection, and command execution caused by unvalidated model output and by insecure generated code (LLM10)

## 15.3 Data, retrieval, and the supply chain

- Sensitive data exposure through responses, prompts, logs, tool-call records, embeddings, and fine-tuning data, and the role of data minimization (LLM02)
- Pre-trained models, adapters, datasets, and packages as supply chain components, including tampered artifacts and invented package names (LLM04)
- Poisoning of training, fine-tuning, and retrieval data, and its lasting effect on model behavior (LLM05)
- Embeddings and vector databases in retrieval-augmented generation (RAG) (LLM09)
- Cross-tenant leakage, missing access control, and manipulated retrieval in vector stores (LLM09)
- Why retrieval must enforce the access rights of the requesting user

## 15.4 Reliability and resource use

- Misinformation as plausible but incorrect output, and overreliance on it by people or automated processes (LLM07)
- Grounding, source attribution, and human verification as ways to reduce the effect of misinformation (LLM07)
- Uncontrolled token, model, and tool usage causing cost overruns, service disruption, or model extraction (LLM06)
- Limits on tokens, cost, request rate, and recursion as controls for unbounded consumption (LLM06)
- Authentication and monitoring of access to model APIs (LLM06)

## Part B – Agentic applications and MCP

## 15.5 Excessive agency and agent design

- An agent as an application in which a model chooses tools and actions, and how it differs from a chat application
- Excessive functionality, excessive permissions, and excessive autonomy as the causes of excessive agency (LLM03)
- Agent identities and credentials, and why an agent must not hold more privilege than its task needs
- Enforcement of authorization outside the model, in the component that runs the tool
- Human approval for high-impact or irreversible actions
- Action logging and limits that stop runaway loops

## 15.6 OWASP Top 10 for Agentic Applications 2026

- The risk areas by identifier: ASI01 Agent Goal Hijack, ASI02 Tool Misuse and Exploitation, ASI03 Identity and Privilege Abuse, ASI04 Agentic Supply Chain Vulnerabilities, ASI05 Unexpected Code Execution, ASI06 Memory and Context Poisoning, ASI07 Insecure Inter-Agent Communication, ASI08 Cascading Failures, ASI09 Human-Agent Trust Exploitation, ASI10 Rogue Agents
- How agent risks extend LLM Top 10 risks, for example how agent goal hijack extends prompt injection
- Persistent memory as a place where poisoned content can influence later sessions
- Trust boundaries between agents, and why a message from another agent is untrusted input

## 15.7 Model Context Protocol security

- MCP as a protocol through which a client connects a model to tools and data provided by servers
- Tool poisoning, in which a tool description or schema contains instructions aimed at the model
- Tool definitions that change after approval, and tools that shadow or impersonate other tools
- Token mismanagement, secret exposure, and forwarding of tokens to upstream services
- Privilege escalation through broad scopes, and the need for narrow, per-server credentials
- Command injection and unsafe execution in MCP servers
- Untrusted and unapproved MCP servers as a supply chain risk
- Prompt injection through tool return values and over-shared context
- Sandboxing, authentication, human approval, and audit logging as MCP controls
